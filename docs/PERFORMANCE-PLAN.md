# Flint 性能优化方案（第六轮 · 先测后改）

> 依据：benchmarks/SUMMARY.md 三轮实测数据 + 已知局限清单
> 核心原则：**热点数据先行**——批次 0 产出分布表之前，不动任何优化代码
> 纪律：每批次 S1 基线快照 → S2 单变量隔离 → S3 反向验证；验证失败 ≤3 次即报告停止
> 当前基线（2026-09-25 安静窗口实测）：万页 3530ms · MDN 7086ms · L3 复杂主题 1112ms · 增量 75ms
> （L3 分层峰值内存 407MB 为 09-24 轮采样值，安静轮未复采）
>
> **⚠️ 批次 0 已完成，方案经热点数据重排**（详见 benchmarks/HOTSPOTS.md）：
> 万页 AOT 构建 74.5% 时间在文件写入（NTFS 物理开销，应用层并行无效），渲染仅 15.5%。
> 原批次 1（并行度）被数据证伪（写入/渲染均已并行，dop 8→128 零敏感性），
> 已降级为"写入 sync 化"小项；渲染执行层提前为批次 1。

## 批次 3 · 内存优化（✅ 已完成——DATAS 确认受益；L3 trade-off 定位；轻量投影待用户裁决）

| # | 结论 | 数据 |
|---|------|------|
| 3.1 | **DATAS 已默认启用且必要**（.NET 9+ 默认开，非"待启用"项）。S3 反向验证：禁用后万页 RSS 365→774MB（+112%），时间无差。保持默认 | psutil 同轮采样 2×2 组 |

| 3.4 | **内存现状复测**（当前版本 + DATAS）：万页 Flint 351/337MB vs Hugo 436/412MB（USS -18%）；MDN 917/899 vs 1431/1406（USS -36%） | memory-bench 3 轮中位 |

**3.3 裁决（2026-09-09）**：**搁置**（推荐项默认执行，未收到相反裁决，可随时推翻）。依据：① 收益上限受限于"遍历全量转换仍发生"——真实模板几乎都遍历全站列表；② L4 新数据显示内存主战场在图片管线（+281MB）而非对象树结构；③ 懒求值语义回归风险与护栏成本不对称。若后续 Hugo 对照显示 L3 内存 trade-off 成为用户可感知问题，重新评估。

## 全程纪律

1. 每批开始：S1 基线快照（命令 + 退出码 + 关键数字）记录在案
2. 每次只改一个变量，改完即测即记录（S2）
3. 任何优化因子采纳前反向验证：移除后必须退化回基线，否则丢弃（S3）
4. 修复尝试 ≤3 次：分析 → 针对性修复 → 换方案 → 报告停止
5. 每批完成即 commit（`checkpoint: 批次N-<里程碑>`），文档同批同步（三方一致）
6. 长任务进度汇报：总体百分比 + 累计已完成 + 未完成 + 下一步
