# Flint 性能优化方案（第六轮 · 先测后改）

> 依据：benchmarks/SUMMARY.md 三轮实测数据 + 已知局限清单
> 核心原则：**热点数据先行**——批次 0 产出分布表之前，不动任何优化代码
> 纪律：每批次 S1 基线快照 → S2 单变量隔离 → S3 反向验证；验证失败 ≤3 次即报告停止
> 当前基线：万页 3433ms · MDN 5431ms · L3 复杂主题 1592ms / 内存 408MB · 增量 51ms

| # | 信号 | 数据 | 判定 |

| 1 | 并发加速比仅 1.04~1.08x（32 核） | 三轮一致 | 最反常——串行段过大或指标语义不明，动手机前必须查清 |

## 执行顺序与依赖

```
批次 0（热点画像）
   ├→ 批次 1（并行度）—— 范围由 0.1/0.2 定
   ├→ 批次 2（渲染执行）—— 范围由 0.2 定
   ├→ 批次 3（内存）—— 3.1 独立可先行；3.3 依赖 3.2
   └→ 批次 4（真实画像）—— 独立，可穿插
        └→ 批次 5（收尾同步）
```

批次 1/2/3 的**先后由批次 0 的热点占比决定**——占比最大的先做。

## 全程纪律

1. 每批开始：S1 基线快照（命令 + 退出码 + 关键数字）记录在案
2. 每次只改一个变量，改完即测即记录（S2）
3. 任何优化因子采纳前反向验证：移除后必须退化回基线，否则丢弃（S3）
4. 修复尝试 ≤3 次：分析 → 针对性修复 → 换方案 → 报告停止
5. 每批完成即 commit（`checkpoint: 批次N-<里程碑>`），文档同批同步（三方一致）
6. 长任务进度汇报：总体百分比 + 累计已完成 + 未完成 + 下一步
