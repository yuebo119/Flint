# 命令行效率工具箱笔记

## 一句话定位

这套笔记记录日常命令行效率工具的组合用法：用更快的工具替换系统自带命令，再用管道把它们串成工作流。核心思想不是收集工具，而是减少"眼睛到信息"之间的步骤：找文件更快、看内容更清楚、筛数据更省心。这条思想线的源头是 Unix 的"做好一件事再组合"的哲学，[Grep](https://zh.wikipedia.org/wiki/Grep) 这类老工具至今仍是每一条管道的基石。评价一个工具值不值得装，标准不是 star 数，而是"每天少按几次退格"：找文件从敲三遍 cd 变成一条 fd，看日志从 cat 变成 bat 带行号，日积月累省下的是注意力而不是秒数。

![命令行工具组合管道示意](/images/demo-10.svg)

## 安装与环境

多数工具在包管理器里都有，一行一个；追求新版可以用 `cargo`、`go install` 或 Homebrew。装完不必急着改默认行为，先把新工具"加"进来，确认顺手再考虑 alias。这份清单按层次分，不追求全，追求每个位置都用最顺手的那个。

最小效率集合一行装齐：macOS 用 `brew install ripgrep fd bat eza jq fzf tldr starship`，Debian/Ubuntu 用 `sudo apt install ripgrep fd-find bat jq fzf`；注意 Debian 系上 fd 的二进制叫 `fdfind`，装完加个别名才顺手。这份清单按层次分，不追求全，追求每个位置都用最顺手的那个。

## 核心用法

### 第一层：定位与搜索

### 第一层：定位、搜索与查看

`fd` 找文件，`ripgrep`（`rg`）找内容。fd 默认忽略 gitignore 与隐藏文件，`fd -e md` 按扩展名找，`fd -t d config` 只找目录；rg 的参数在前面那篇笔记里专门记过，这里只强调组合：`rg -l pattern` 先粗筛出文件，再交给下一层工具处理，比单工具层层过滤快得多。fd 与 rg 是"找"的两面：一个按名字，一个按内容，两者输出可以互当输入，这就是命令行组合的起点。

`bat` 替代 `cat`：语法高亮、行号、Git 修改标记，`-n` 强制行号，`-r 10:20` 只看一段。`eza` 替代 `ls`：`eza -la --tree --level 2` 带树形展开，长目录结构一眼看完。`tldr` 替代 `man`：只要例子，`tldr tar` 直接给常用组合，查语法时比翻手册快十倍。查看层的共同追求是"少滚屏"：bat 的行号与高亮减少定位时间，eza 的树形减少目录往返，tldr 的例子减少试错，三个工具都在缩短"看到答案"的路径。

```bash
# 找最近七天改过的 markdown
fd -e md --changed-within 7d

# 找内容再收窄到类型：rg 列文件，fd 过滤
rg -l "TODO" | fd -e rs

# 带高亮与行号看文件
bat -n src/main.rs

# 只看中间一段（10 到 20 行）
bat -r 10:20 config.yaml

# 树形看两层目录
eza -la --tree --level 2

# 只要例子的手册
tldr fd
```

### 第二层：处理与选择

`jq` 处理 JSON：`jq '.items[] | {id, name}'` 提取字段，管道接 curl 就是接口调试台。`fzf` 是模糊选择器，接管"从一堆选项里挑一个"的场景：`Ctrl+R` 搜历史、`Ctrl+T` 挑文件、路径补全，装完还要跑 shell 集成（`eval "$(fzf --bash)"`）这些键位才在。处理层的原则是"能管道就不落盘"：curl 的输出直接进 jq，jq 的结果直接进 fzf，中间文件一个都没有，调试完不留垃圾，思路也不被打断。

```bash
# curl 接 jq：接口调试台
curl -s https://example.com/api/items | jq '.[] | {id, name}'

# fzf 交互选择文件并编辑
$EDITOR $(fzf)

# 从历史命令里搜一条执行
history | fzf --tac
```

### 第三层：会话与提示符

`tmux` 保会话：SSH 断了重连窗口还在，分屏、多窗口、`tmux attach` 一键恢复。`starship` 是跨 shell 的提示符，把 git 分支、Node 版本、上条命令耗时直接显示在命令行里，配置集中在 `~/.config/starship.toml`，改完立即生效，不用装插件。

```toml
# ~/.config/starship.toml
[character]
success_symbol = "[>](bold green)"
error_symbol = "[x](bold red)"

[git_branch]
format = "[$symbol$branch]($style) "
style = "bold purple"

[cmd_duration]
min_time = 2000
```

### 组合成工作流

单个工具是零件，管道才是机器。三条经过实战的工作流：交互式清理（fd 找文件 → fzf 多选 → xargs 执行）；日志现场（tail -f 实时 → rg 过滤 → bat 高亮）；接口联调（curl 请求 → jq 整形 → fzf 选段）。写工作流的要领是每步只做一件事，输出格式对下一步友好，这样任何一环都能被单独替换。

```bash
# 工作流一：交互式清理构建产物
fd -H -t d -E .git node_modules | fzf --multi | xargs -r rm -rf

# 工作流二：实时看日志里的错误，带高亮
tail -f app.log | rg --colors always "ERROR|WARN" | bat -p -l log

# 工作流三：接口联调，逐条响应交给 fzf 翻看
curl -s https://example.com/api/items | jq -c '.[]' | fzf --preview 'echo {} | jq'
```

### 值得养成的三个习惯

习惯一：管道优先。遇到"重复三步的操作"，先想管道，再想脚本，最后才想写程序；命令行是思考的草稿纸，多数需求在草稿纸上就解决了，根本到不了写程序那一步，提前写程序反而是用复杂换心安。

习惯二：第三次就固化。同一个命令敲到第三遍，就该写成 alias 或函数；alias 只服务交互终端，脚本和 CI 里用函数或独立脚本，边界清晰，两边都不委屈，也不会出现"脚本里 alias 不生效"的灵异事件。

习惯三：定期盘点。每季度翻一次 shell 历史，频率最高的十条就是下一个该工具化的候选；工具箱要流动不要囤积，三个月没用的工具，卸了比留着踏实。把好用的组合记进自己的笔记，换机器时 dotfiles 加笔记，半小时重建整套工作环境。

这三个习惯都不涉及具体工具，却是工具箱能持续增值的原因；工具会过时，习惯不会。

## 工具分层速查

按"从定位到落地"的使用顺序分层，每层记一个主力，认不全所有工具没关系，每层顺手就够：

- **定位**
  - `fd`：找文件，默认尊重 gitignore
  - `rg`：找内容，参数见前面的 ripgrep 笔记
  - `tldr`：查用法，只要例子不要手册
- **查看**
  - `bat`：带高亮与行号看文件
  - `eza`：树形看目录结构
  - `less -R`：任何长输出的分页终点
- **处理**
  - `jq`：JSON 提取与变换
  - `sed` / `awk`：行级文本处理，系统自带
  - `xargs`：把管道输出变回命令参数
- **选择**
  - `fzf`：模糊选择，接管历史、文件、进程列表
  - `zoxide`（`z`）：目录跳转，习惯后回不去层层 `cd`
- **会话**
  - `tmux`：会话保持与分屏
  - `starship`：提示符，信息密度优先

## 高频组合速查

八条组合按"清理、查看、调试"分组，全部可以直接粘进终端跑，跑通一条再改参数。

| 目标 | 组合 | 说明 |
| --- | --- | --- |
| 找大文件 | `eza -la --sort size` 或 `du -sh * | sort -h` | 排序参数别记反 |
| 交互删文件 | `fd -e log | fzf --multi | xargs rm` | `--multi` 多选要慎用 |
| 搜历史并执行 | `history | fzf --tac` | 确认后再回车执行 |
| JSON 接口调试 | `curl -s ... | jq` | 配合 `less` 翻长响应 |
| 监控日志 | `tail -f app.log | bat -p -l log` | `-p` 纯文本不分页 |
| 快速跳目录 | `z project` | 比层层 `cd` 快 |
| 看目录结构 | `eza --tree --level 2` | 陌生项目第一眼 |
| 查命令例子 | `tldr docker build` | 比搜索引擎快 |

## 上手清单

按这个顺序一周装一层，不要一次全上。一次装全的新鲜感通常撑不过三天，按周推进的理由是让每个工具长进肌肉记忆，而不是躺在配置里吃灰：

- [ ] 第一周：`rg` + `fd`，只替换搜索动作
- [ ] 第二周：`bat` + `eza`，替换查看动作
- [ ] 第三周：`jq` + `fzf`，把管道升级成交互选择
- [ ] 第四周：`tmux` + `starship`，固定工作环境
- [ ] 全程：用 `tldr` 查例子，减少查文档的打断
- [ ] 最后：把顺手的组合写成 alias 或小函数，收进自己的 dotfiles

## 踩坑记录

> **坑一：fzf 的键位没生效。** 只装了二进制，没跑 shell 集成：`eval "$(fzf --bash)"`（zsh 用 `--zsh`）。键位没有 = 集成没加载，和装没装无关。

> **坑二：jq 报错信息看不懂。** `jq: error: syntax error` 后面会跟程序片段位置，先把表达式拆短：先 `.[]` 再一层层加过滤。复杂抽取写进 `.jq` 文件，用 `jq -f filter.jq` 调试比单行快。

> **坑三：bat 在管道里行为怪异。** bat 检测到非 TTY 会自动变"猫模式"，脚本里要稳定行为加 `-p`（plain）与 `--style plain`；要保留分页交互才用默认模式。

> **坑四：alias 写进交互配置，脚本里却不生效。** alias 默认不展开于非交互 shell，把要复用的逻辑写成函数或脚本放进 `PATH`，脚本和命令行都能用，这才是一次编写两处执行。

> **坑五：盲目迁移默认命令惹恼协作者。** 在共享服务器把 `cat` 全局 alias 成 `bat`，别人的脚本行为全变。新工具用原名，alias 只在自己的 shell 配置里生效，是对他人最基本的尊重。

## 速查小结

- 工具箱分五层：定位、查看、处理、选择、会话，每层一个主力。
- 工具的价值在组合：`rg | fzf | xargs` 就是一条交互工作流。
- 新工具先用原名，确认顺手再 alias，别动全局默认。
- 可复用的逻辑写成函数或脚本，不要只躺在 alias 里。
- `tldr` 查例子、`man` 查细节，两个都要，别互相取代。
- 工作流三例子：`fd → fzf → xargs`、`tail → rg → bat`、`curl → jq → fzf`。
- 一周上一层，形成肌肉记忆再装下一个，别让学习成本反噬效率。

命令行的效率不来自工具数量，来自"手比脑子先到"的那几下按键。最后一句话留给选择标准：工具是手的延伸，不是身份标签，用得上才装，用不上就卸，别让工具箱变成负担。
