Markdown 的核心语法半小时就能学会，真正让人反复查资料的是各家实现的"扩展语法"：表格在有的渲染器里居中，在有的里面错位；脚注在编辑器里正常，发布后编号错乱；折叠块本地预览好好的，上线后整块消失。这篇参考手册把常用扩展语法集中列出，标注写法、渲染差异与适用场景，供写作时随时查阅。文中以 Hugo 使用的 goldmark 渲染引擎的默认配置为主要参照[^1]。

## 基础语法要点

这一组属于核心语法或接近核心，所有渲染器都支持，优先级最高。

### 段落与换行

Markdown 中段落之间必须空一行。同一段落内强制换行有两种写法：行尾敲两个空格，或用反斜杠结尾。两种方式渲染结果一致，但反斜杠在部分工具里会被当成转义字符处理，推荐统一用两个空格。另外，中文写作有一个常见坑：行尾直接回车在部分渲染器里不会换行，而是把两行拼成一段，发布前务必在预览环境确认。

### 标题与锚点

H1 到 H6 用对应个数的 `#` 书写。多数渲染器会为标题自动生成锚点：英文标题转小写并把空格换成连字符，中文标题按字面保留。写标题时避免使用纯标点开头，同一文档内标题文本不要重复，否则锚点会冲突，目录链接会跳到错误位置。一篇文章建议只用一个大标题（H1），正文从 H2 开始，层级不要跳级。

### 列表深入

- 无序列表用 `-`、`*` 或 `+` 开头，同一文档统一用一种符号，diff 更干净。
- 有序列表用数字加点，实际渲染编号由渲染器生成，写成 `1.` `1.` `1.` 也能得到一二三。
- 列表项之间空一行会变成"松散列表"，每项带上下间距，适合项内有多段落的情况。
- 嵌套列表缩进两个或四个空格均可，但同一份文档内要统一，否则源码层次混乱。
  - 这是二级列表，用于补充说明父项。
  - 再深一层通常就该拆表了，三层以上的列表可读性很差。

### 链接的三种写法

行内式最常用：`[链接文字](https://example.com "可选标题")`。参考式把地址集中到文末，正文更干净，适合同一链接多次引用。自动链接直接用尖括号包裹地址，如 `<https://example.com>`，多数渲染器也会自动识别裸 URL。无论哪种写法，链接文字都要能独立表意，"点击这里"和"这篇"在脱离上下文后没有信息量，对读屏软件也不友好。

### 转义与特殊字符

反斜杠可以转义 Markdown 中有特殊含义的字符：`\*`、`\_`、`\#`、`\[` 等。代码块与行内代码中的内容不参与解析，是最安全的写法。需要原样展示一段 Markdown 源码时，用四个反引号包裹三重反引号的示例，这是写语法文档的标准技巧。

还有一个高频问题是无序列表符号后的空格：`-文字` 在多数渲染器里不会被识别成列表，必须写成 `- 文字`。类似地，标题的 `#` 后、引用的 `>` 后也都需要一个空格。这些小细节不会报错，只会让你的源码在别人的渲染器里变成一段普通文字，排查起来格外费时。

## 扩展语法详解

这一组依赖渲染端支持，用之前对照文末的兼容性表确认目标环境。

### 表格

表格用竖线分隔单元格，第二行是分隔线，通过冒号控制对齐方式。任务列表则用复选框表达待办，两者是最常用的扩展：

```markdown
| 左对齐 | 居中对齐 | 右对齐 |
|:-------|:--------:|-------:|
| 短文本 | 长一些的文本 | 12345 |

- [x] 已完成的事项
- [ ] 未完成的事项
  - [ ] 子任务缩进两个空格
```

表格的要点：分隔线至少三个字符（`---`、`:---`、`---:`），两侧竖线可省略但建议保留；单元格内不能出现未转义的竖线，需要时写成 `\|`；表格前后必须留空行，否则部分渲染器会把表格当成普通段落；表头控制在十个字以内，超过四列就该考虑拆分成列表。任务列表的子项缩进两个空格最稳，用 Tab 在不同编辑器里宽度不一致，容易解析错位。

### 脚注

脚注用于放置补充说明，不打断正文阅读节奏。写法是在引用处写 `[^1]`，在文章任意位置写定义；定义列表则由"术语、冒号、释义"三行组成，适合词条式内容：

```markdown
静态站点生成器把 Markdown 转成 HTML[^1]。

[^1]: 常见的静态站点生成器包括 Hugo、Jekyll 与 Eleventy。

静态站点生成器
: 把 Markdown 与模板编译为静态 HTML 的程序。
```

脚注编号会自动按引用顺序生成，中途增删条目不必手动改号，这是它相对手工编号的核心优势；定义可以集中放在全文末尾，也可以放在对应章节之后，渲染结果一致。定义列表的释义部分支持多段落和嵌套列表，术语较多时也可以改用表格，横向检索效率更高。

### 折叠块

折叠块用 `<details>` 与 `<summary>` 实现，默认折叠长内容，适合放参考答案、完整日志或进阶说明：

```html
<details>
<summary>点击展开：常见报错与处理</summary>

页面空白时先检查模板是否存在，再看构建日志中的模板错误行号。

</details>
```

需要注意，折叠块属于原始 HTML，渲染端必须允许内嵌 HTML 才会生效。Hugo 中需要设置 `markup.goldmark.renderer.unsafe = true`；GitHub 与多数文档平台默认允许。使用折叠块时确保折叠之外有足够信息，避免读者漏掉关键内容；`<summary>` 的文字要能独立表意，"点击查看详情"不如"点击展开：常见报错与处理"。

## 速查与选用

### 其他常用语法速查

| 语法 | 效果 | 说明 |
|------|------|------|
| `**粗体**` | 粗体 | 用于关键结论，一段不超过两处 |
| `*斜体*` | 斜体 | 表示术语首次出现或强调 |
| `~~删除线~~` | 删除线 | 表示废弃内容 |
| `` `行内代码` `` | 行内代码 | 命令、文件名、参数名专用 |
| `> 引用` | 引用块 | 引述他人观点或提示信息 |
| `[文字](url)` | 链接 | 文字要能独立表意 |
| `![图注](url)` | 图片 | 图注必写，服务无障碍阅读 |
| `---` | 分割线 | 分隔大章节，一篇不超过三处 |

### 兼容性速查表

不同渲染器对扩展语法的支持并不一致，写作前对照下表可以避免返工：

| 语法 | CommonMark | GitHub | Hugo 默认 |
|------|:---------:|:------:|:---------:|
| 表格 | 否 | 是 | 是 |
| 任务列表 | 否 | 是 | 是 |
| 脚注 | 否 | 是 | 是 |
| 删除线 | 否 | 是 | 是 |
| 定义列表 | 否 | 否 | 是 |
| 折叠块 | 否 | 是 | 需开启 unsafe |
| 数学公式 | 否 | 是 | 需 KaTeX 或 MathJax |

数学公式依赖渲染端集成 KaTeX 或 MathJax，行内公式用单个美元号包裹，块级公式用双美元号。发布类文章用到公式的概率不高，真要用时优先考虑截图或专用工具渲染，避免拖慢页面加载。

### 选用建议

> 语法选用的总原则：先保证在任何渲染器里都不出错，再按需启用收益明确的扩展。

- 默认只用核心语法加表格，兼容性最好，迁移成本最低。
- 任务列表和脚注收益高、风险低，可以放心用。
- 折叠块与数学公式依赖渲染端配置，发布前务必在目标环境验证一次。
- 不用为了样式效果嵌套多层 HTML，后期维护和全文检索都是负担。
- 同一份文档在多个平台分发时，以支持面最窄的平台为准做减法。
