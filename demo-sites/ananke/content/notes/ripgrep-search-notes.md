# ripgrep 搜索技巧笔记

## 一句话定位

ripgrep（命令是 `rg`）是递归搜索文件内容的工具，grep 的现代替代品：默认忽略 `.gitignore` 里的内容、自动跳过二进制文件、多线程并行搜索，大仓库里快一个数量级。它的设计哲学是"默认就该这么搜"，多数场景一条命令就够。维基百科对 [Ripgrep](https://zh.wikipedia.org/wiki/Ripgrep) 的定位是"面向代码搜索的行导向搜索引擎"，注意"面向代码"这四个字：它的默认行为就是为代码仓库调优的，搜索日志和普通文本时要记得关掉一些默认。反过来说，搞懂这些默认值什么时候该关，是从"会用"到"用好"的分界线。

![ripgrep 搜索结果示意](/images/demo-3.svg)

## 安装与环境

各平台包管理器都有：Debian/Ubuntu 装 `ripgrep`（注意包名和命令名不一样，命令是 `rg`），macOS 用 Homebrew，Windows 用 winget 或 scoop，Rust 工具链用户直接 `cargo install ripgrep`。它只有一个二进制文件，无运行时依赖，扔进 Docker 镜像也能用，很适合放进 CI 镜像。追求最新版时下载 release 页的静态二进制也能直接用，解压即用，不需要 Rust 工具链参与。

```bash
# Debian / Ubuntu：包装名是 ripgrep，命令是 rg
sudo apt install -y ripgrep

# macOS
brew install ripgrep

# Windows
winget install BurntSushi.ripgrep.MSVC

# Rust 工具链用户
cargo install ripgrep

# 确认安装
rg --version
```

## 核心用法

### 基本搜索与过滤

`rg 关键词` 就会递归搜索当前目录，默认打印文件名、行号与匹配行，匹配处高亮。常用过滤：`-i` 忽略大小写，`-w` 全词匹配，`-F` 把模式当字面量（搜 IP、正则元字符时必用），`-l` 只列文件名，`-c` 统计每个文件命中数，`-n` 强制行号。按文件类型过滤用 `-t py`，或者 `-g '*.md'` 通配符，`-g '!*.min.js'` 排除。匹配处默认高亮，颜色方案可以用 `--colors line:fg:yellow` 这类参数微调；输出要交给后续脚本处理时，记得加 `--no-heading` 关掉文件名分组头，格式更规整。

```bash
# 基本搜索：递归当前目录，显示文件名与行号
rg "TODO"

# 忽略大小写 + 全词匹配
rg -iw "error"

# 只列包含匹配的文件名
rg -l "deprecated" src/

# 按类型与 glob 过滤
rg -t py "import torch"
rg -g '*.md' -g '!drafts/**' "发布"

# 搜字面量（IP、路径、正则元字符）
rg -F "192.168.1.1"
```

### 上下文与替换预览

`-A 3` 显示匹配后三行，`-B 2` 前两行，`-C 3` 前后各三行，读日志找上下文时最常用。`-r` 指定替换内容做预览，`--passthru` 会把没匹配的行也打出来，配合 `-r` 就是"搜索即预览"的 sed。`-z` 让 rg 按 NUL 处理多行，配合 `-U` 可以搜跨行内容，比如函数签名和调用隔行的情况。读服务器日志时 `-C` 上下文比 `tail -n` 灵活：日志行有明确的时间戳和级别前缀，`rg "ERROR" -C 2` 能直接把前后的调用链捞出来；`--passthru` 配合 `-r` 还能在终端里预览批量改名的效果，确认无误再落到 sed。

```bash
# 看匹配前后各三行
rg -C 3 "panic:" app.log

# 替换预览：不落盘，只在终端看效果
rg "v1\.2\.3" -r "v1.3.0" --passthru CHANGELOG.md

# 跨行搜索：Go 函数定义与紧随的退出调用
rg -U "func main\(\)\n.*os.Exit" --type go
```

### 输出控制

颜色、分页与统计：结果进管道时 rg 自动关颜色，需要时加 `--colors always` 或用 `--pretty`。结果多的时候管道给 `less -R`，用 <kbd>空格</kbd> 翻页、<kbd>/</kbd> 在结果里二次搜索、<kbd>q</kbd> 退出。`--stats` 在结尾打印搜索了多少文件、跳过多少、耗时多少，调优时很好用；`--sort path` 让输出顺序稳定，方便两次结果对比。另一个实用组合是 `--json`：输出结构化记录，每条匹配带文件、行号、匹配文本，可以直接喂给 jq 做统计，比如按文件聚合命中数、按模块看 TODO 分布。

```bash
# 统计信息：看了多少文件、命中多少行
rg --stats "unwrap\(\)" src/

# 分页浏览长结果
rg "exception" . | less -R
```

### 正则与字面量的边界

rg 默认用 Rust 正则引擎，语法是"保证线性时间"的子集：不支持反向引用和 lookaround，换来的是不会灾难性回溯。需要这两类特性时加 `-P` 启用 PCRE2。拿不准模式含义时，用 `-F` 当字面量搜是最安全的起点；搜代码结构（函数定义、import 语句）再上正则，并善用 `\b` 词边界和 `(?i)` 内联标志。写完的正则先用 `--files-with-matches` 验证命中范围，再决定要不要看上下文。替换预览（`-r`）只改输出不改文件，真正批量改写仍然交给 sed 或编辑器；`-r` 的替换串里可以用 `$1` 引用捕获组，做"给函数统一加前缀"这类重构预览很顺手。

### 参数分层速查

按使用频率把参数分三层，初学者记住第一层就够用。这三层的分界不是功能强弱，而是"多久用一次"：第一层每天用，第二层每周用，第三层遇到特定问题才用，不用强记：

- **第一层：日常**
  - `-i` 忽略大小写、`-w` 全词、`-l` 只列文件
  - `-n` 行号、`-c` 计数、`-A/-B/-C` 上下文
- **第二层：过滤**
  - `-t rust` 按类型、`-T test` 排除类型
  - `-g '*.lock'` 包含 glob、`-g '!target/**'` 排除 glob
  - `--hidden` 搜隐藏文件、`--no-ignore` 连 `.gitignore` 一起搜
- **第三层：进阶**
  - `-P` 启用 PCRE2 引擎（lookaround、反向引用）
  - `-z` 多行模式、`-U` 跨行正则
  - `-r` 替换预览、`--passthru` 保留未匹配行

### 与其他搜索工具的对照

和 grep 比：grep 的优势是到处都有，POSIX 脚本里它才是最稳的选择；rg 胜在默认行为聪明与速度。结论是交互搜索用 rg，可移植脚本用 grep，两个都装不冲突，也别在脚本里假设 rg 存在。

和 IDE 搜索比：IDE 强在跳转、重构、引用分析，rg 强在脚本化、管道、远程服务器；日常"这个函数在哪被调用"用 IDE，"这个配置项整个仓库有几种写法"用 rg，互补而非替代，谁也不必卸载谁。

和 find 比：find 按属性找（时间、大小、权限），rg 按内容找，场景几乎不重叠；fd 是 find 的现代替代，在工具箱那篇笔记里细说，别把三者混着用，也别用 rg 去干 find 的活。

迁移成本方面，从 grep 到 rg 只需要记住三条：默认递归当前目录、默认尊重 ignore 文件、默认跳过二进制；其余常用参数与 grep 基本同名，`-i`、`-w`、`-l`、`-c`、`-n` 直接照搬，半小时就能无缝切换，切换完就回不去了。

## 高频场景速查

下面十条按"搜代码、搜日志、搜配置"三类归拢，日常遇到先来表里对号入座，再回上面的用法示例取完整命令。

| 场景 | 命令要点 | 说明 |
| --- | --- | --- |
| 找 TODO | `rg "TODO"` | 默认递归当前目录 |
| 只看文件列表 | `rg -l pattern` | 脚本里判断"有没有"最快 |
| 统计命中数 | `rg -c pattern` | 每个文件一行计数 |
| 搜配置项 | `rg -F "key=value"` | 字面量搜索防正则误伤 |
| 排除构建目录 | `-g '!target/**'` | 尊重 gitignore 时补一刀 |
| 搜隐藏文件 | `--hidden --no-ignore` | 找 `.env`、`.github` 内容 |
| 带上下文读日志 | `rg -C 5 "ERROR" app.log` | 比 tail 后翻页直观 |
| 跨行匹配 | `rg -U -z` | 函数签名、日志堆栈 |
| 二进制文件 | `-a` 强制文本搜索 | 默认跳过二进制 |
| Windows 换行符 | `--crlf` | CRLF 仓库的匹配修正 |

## 踩坑记录

这五条覆盖了 rg 与其他工具混用时最容易困惑的地方，遇到"结果不对"先按顺序排查一遍，多数情况能自己定位，不用换工具。

> **坑一：搜不到刚加的文件。** rg 默认尊重 `.gitignore` 与 `.ignore`，被忽略的目录（比如 `dist/`、`node_modules/`）根本不会进索引。确认用 `--hidden --no-ignore` 再搜一次，别急着怀疑工具。

> **坑二：搜 IP 搜出一堆乱匹配。** 点号在正则里是任意字符，`192.168.1.1` 会匹配到 `192x168a1b1`。搜这类字面量一律加 `-F`，或者把点号转义。

> **坑三：`-P` 之后慢得像蜗牛。** PCRE2 引擎没有 Rust 正则的线性时间保证，回溯灾难时能卡死。lookaround 需求先想想能不能拆成两次普通搜索。

> **坑四：管道给 grep 之后颜色没了、高亮也没了。** rg 检测到非 TTY 会关颜色，要颜色加 `--colors always`；行号在管道里默认保留，丢的是高亮，别搞反。

> **坑五：`-c` 统计和肉眼数不一致。** `-c` 数的是"命中行数"不是"匹配数"，一行里三个 TODO 只算一。要数匹配总数用 `rg -o pattern | wc -l`，`-o` 只输出匹配片段，交给 wc 数行。

> **坑六：中文搜索命中不全。** 源文件编码不是 UTF-8 时（老项目的 GBK），rg 默认按 UTF-8 解码，中文会搜不到。先用 `file -bi 文件名` 确认编码，GBK 文件用 `iconv -f gbk -t utf-8` 转一份再搜；让团队把编码统一掉才是根治。

## 速查小结

- 默认行为已经为代码仓库调优：gitignore、二进制跳过都是自动的。
- 搜字面量用 `-F`，搜结构用正则，拿不准先 `-F` 试。
- 过滤优先级：`-t`/`-T` 按类型，`-g` 按路径，`--no-ignore` 是最后大招。
- 上下文 `-C` 是读日志的神器，比打开编辑器翻快得多。
- 正则引擎是 Rust 版子集，lookaround 需求先想 `-P` 或拆两步。
- 长结果管道给 `less -R`，空格翻页、`/` 搜索、`q` 退出。

搜索是理解代码库的第一步，rg 把这一步的摩擦降到接近于零。更大的收益在于它可以进脚本、进 CI：禁止提交某段代码、扫描密钥特征、统计技术债，这些自动化都从一条搜索命令开始。最后提醒：工具越顺手越要定期回看默认值，rg 的默认行为本身就是一份"代码仓库该长什么样"的最佳实践清单。
