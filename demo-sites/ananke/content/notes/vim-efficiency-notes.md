这篇笔记整理我真正留在肌肉记忆里的 Vim 操作。标准很苛刻：一年用不到三次的，再酷也不记；一天要用十次的，再基础也写。Vim 的学习曲线众所周知，但我的体会是，曲线的前半段被人为夸大了，真正难的是没人告诉你该按什么顺序练。顺序错了，就会在插件市场里泡三个月，回头发现 `ci"` 都没用过。

## 先学移动，再谈插件

Vim 的效率不来自插件数量，来自手不离主键区。`hjkl` 只是入门，真正的加速器是这些：

- 词级移动：`w` 下一个词头，`b` 上一个词头，`e` 当前词尾
- 行内跳转：`f{char}` 行内跳到指定字符，`t{char}` 跳到它前面，`;` 重复上一次
- 段落跳转：`{` `}` 按空行分段，代码里等于按函数块跳
- 匹配跳转：`%` 在配对的括号间来回飞
- 屏幕级：`H` 屏顶，`M` 屏中，`L` 屏底，配 `zz` 把当前行滚到屏幕正中

这套移动练熟的标准是：眼睛盯着屏幕，手不用找方向键。没达到这个标准之前装任何插件都是逃避，因为插件的本质是"更快的到达"，而到达的基本功是移动。`f` 键值得单独夸：行内任何字符，两三次按键必达，比鼠标快一个数量级，也比 `w` 精确得多。移动熟练的另一个标志是很少用全文搜索定位：能用 `w`、`f`、`{` 三步到达的位置就别 `/` 搜，精确移动比模糊搜索更可控，也不会把下一屏的内容冲掉。

## 我的核心映射

映射只留真正高频的，多一个都是记忆负担：

| 按键 | 作用 | 说明 |
|------|------|------|
| <kbd>Space</kbd>+<kbd>w</kbd> | 保存 | leader 设为空格，拇指最舒服的位置 |
| <kbd>Space</kbd>+<kbd>f</kbd>+<kbd>f</kbd> | 找文件 | 日常入口，代替文件树 |
| <kbd>g</kbd><kbd>c</kbd><kbd>c</kbd> | 注释切换 | 视觉模式下批量注释整段 |
| <kbd>-</kbd> | 打开文件树 | 目录结构总览时才用 |
| <kbd>Tab</kbd> | 下一个缓冲区 | 配 <kbd>Shift</kbd>+<kbd>Tab</kbd> 回上一个 |

leader 键设为空格是这个配置里最关键的决定。默认的 `\` 在小指远端，按久了累；空格最大最好按，组合出来的快捷键容错高。改 leader 是五分钟的事，收益是长期的，建议第一次写 vimrc 就改掉。映射在精不在多，我的配置里自定义映射常年保持在十个以内，每加一个都要过三问：一周用几次？有没有原生操作能达到同样效果？记不住的话值不值？三问过两关才留下。

## 文本对象：Vim 的杀手特性

### 引号与括号

文本对象是 Vim 区别于其他编辑器的核心设计：把"编辑的单位"从字符扩展到结构。`ci"` 改双引号里的内容，`ca(` 改圆括号连同括号本身，`da[` 删方括号加内容。动词加对象，两个维度组合出全部编辑动作，`y`、`d`、`c` 三个动词配一大家子对象，覆盖日常九成编辑。

举个小例子就能看出威力：把函数参数列表里的内容整个换掉，光标在括号里任何位置，`ci(` 一次到位，不用先挪到括号再选中。刚转 Vim 的人看到这个操作，通常会沉默一会儿，然后开始重学自己写了五年的代码。

### 段落与缩进对象

`cip` 改整个段落，光标落在段内任意位置都行；`>i{` 按花括号块增加缩进；`=%` 按缩进重新格式化选中区域，整理从别处粘贴过来的错位代码是神器。还有 `it` 和 `at` 一对标签对象，处理 HTML 时选中标签内内容和整个标签，改前端模板的效率直接翻倍。这些对象全部支持动词前缀，`y`、`d`、`c` 通吃，还能配数字前缀，比如 `3cip` 连改三段。文本对象是 Vim 里少有的学一次终身受益的特性，回报率远超任何插件。Vim 文本对象的参考列表在 <https://zh.wikipedia.org/wiki/Vim> 的文档链接里能查到完整版。

## 搜索与替换：:%s 的完整姿势

替换是编辑器里性价比最高的命令，Vim 的写法一行覆盖全局：

```bash
# 全文替换，逐个确认
:%s/old/new/gc

# 只看不改，先数数有几处
:%s/old/new/gn

# 限定在可视选区范围内替换
:'<,'>s/old/new/g
```

`c` 结尾是逐个确认，`n` 是只报数量。大替换之前先 `gn` 数一遍，是这个命令的安全带。范围词也值得记：`%` 全文，`'<,'>` 选区，`.`, 当前行。替换支持正则和反向引用 `\1`，批量改命名、改配置项比交互式替换可靠，因为可复现，错了撤销也有明确边界。

## 为什么我劝你别急着装 IDE

经常有人问 Vim 和 IDE 怎么选，我的答案一直没变：先问自己每天在哪花时间。如果八小时在改代码，IDE 的语义跳转、重构工具、调试器是实打实的生产力；如果八小时在读日志、改配置、SSH 到各台机器，Vim 的"哪儿都有它"更值钱。我的实际分工是：本地大项目用 IDE，远程运维和快速修改用 Vim，两者不是替代关系，是场景分工。真正低效的是在错误的地方执着于顺手的工具，为了用 Vim 在 IDE 项目里硬撑，或者为了图形界面给每台服务器装桌面环境。

## 读代码的三个习惯

编辑之外，Vim 读代码也有一套顺手操作，都是日常验证过的：

- 看函数列表：先 `:vimgrep /^func/ %` 再 `:copen`，比滚动翻找快一个量级
- 跳转与返回：`gd` 到定义，<kbd>Ctrl</kbd>+<kbd>o</kbd> 跳回去，<kbd>Ctrl</kbd>+<kbd>i</kbd> 再前进
- 折叠：`zc` 折起，`zo` 展开，长函数先折叠看骨架再逐段细读

`gd` 加 `Ctrl+o` 这套组合是读陌生代码的主力：顺着一串调用往下钻，迷路了就一层层跳回去。配合折叠看骨架，陌生项目半小时能建立起结构感，比从头顺读高效得多。

## 最小可用 vimrc

我的配置观是：先裸写两周，每觉得"要是有个功能"就记下来，两周后一次性配。这样配出来的每行都有出处，不会抄一堆看不懂的选项。这是精修后的最小集：

```text
set number relativenumber
set ignorecase smartcase
set expandtab tabstop=4 shiftwidth=4
set incsearch hlsearch
set clipboard=unnamedplus
let mapleader = " "
nnoremap <Space>w :w<CR>
nnoremap <Space>ff <cmd>Files<CR>
nnoremap gcc <cmd>Commentary<CR>
```

先确认环境再谈配置，查看当前构建支持的特性：

```bash
vim --version | head -3
vim --version | grep clipboard
```

`clipboard=unnamedplus` 依赖系统剪贴板支持，老版本或精简安装可能没有，`grep` 一下确认再开，否则每次启动都报错。相对行号配 `number` 是黄金组合：当前行显示绝对行号方便跳转，其余行显示相对距离方便数行数，`5j`、`3k` 这种操作有了数字依据。

## 退出插入模式的正路

新手最折磨的问题是"怎么退出插入模式"。标准答案是 <kbd>Esc</kbd>，更快的答案是 <kbd>Ctrl</kbd>+<kbd>[</kbd>，手指不用离开主键区。更激进的玩法是把 CapsLock 改成 Esc，硬件层面解决，改一次受益所有编辑器。这个改动在操作系统层面做，Vim 这里只提醒一句：值得。

搜索之后用 <kbd>Enter</kbd> 确认、<kbd>n</kbd> 跳下一个、<kbd>N</kbd> 跳上一个，<kbd>*</kbd> 直接搜光标下的单词，这套组合是读代码的高频路径。配 `incsearch` 之后边打边高亮，搜索体验和现代编辑器对齐，但手不用离开键盘。

## 练习路线

最后给一条我验证过的练习路线，按顺序来，每步一周：

1. 第一周只用 `hjkl` 加 `w` `b`，逼自己不用方向键，先建立移动本能
2. 第二周攻文本对象，`ci"`、`ci(`、`cip` 各练到闭着眼睛能按
3. 第三周学 `f`、`;`、`%` 和标记跳转 `m{a}`、`'{a}`，长文件里练定位
4. 第四周上宏，`qa` 录制、`@a` 重放、`@@` 重复上次，体会一次录制百次执行的爽感

四周之后回头看，编辑速度的变化自己都能感觉到。再往后就是按需加插件，那时候你已经分得清哪些是工具真需求，哪些只是新鲜感。
