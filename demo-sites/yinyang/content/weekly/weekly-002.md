这周聊一个监控面板上看不见的成本：上下文切换。代码不会因为它变红，告警不会因为它响铃，但它悄悄吃掉的时间，可能比任何一次线上故障都多。五个条目：切换的成本到底由什么构成、深度工作块怎么保护、异步通信为什么是解药，以及开工仪式和团队公约这些能落地的小事。

![任务切换的隐性成本：注意力残留与工作记忆重载](/images/demo-2.svg)

## 本期速览

| 条目 | 一句话观点 |
| --- | --- |
| 切换的成本不是几分钟 | 大脑留着上一个任务的注意力残留 |
| 深度工作块 | 时间要像会议室一样被预订和保护 |
| 异步通信是解药 | 文档即共享上下文，写清楚再发 |
| 开工仪式 | 降低启动成本，把进入状态变成固定动作 |
| 团队公约 | 文化慢慢变，但有几件事下周就能做 |

## 条目一：切换的成本不是"几分钟"

流行说法是"进入状态要十几分钟"，这个数字低估了切换的代价。心理学里的注意力残留指的是：任务 A 被打断后，一部分注意力仍然挂在 A 上，你人已经在做 B，脑子还在半路。这解释了一个常见体验：刚回完一条消息再看代码，刚才读懂的上下文像被擦掉了一半。更贵的是内部打断：手机震一下，你自愿去看，大脑没有外部警报做铺垫，重启成本反而更高。

### 一张表看清打断的来源

| 来源 | 例子 | 恢复成本 |
| --- | --- | --- |
| 外部，来自他人 | 同事拍肩膀、即时消息 | 中，可以协商 |
| 外部，来自系统 | 告警、构建失败通知 | 单次低，密度致命 |
| 内部，来自自己 | 刷手机、切标签页 | 高，最难防 |

对付内部打断的办法笨但有效：把"看一眼"变成批量动作。每小时固定一个消息窗口，其余时间通知静音。刚开始会焦虑，怕错过事，两周后你会发现，真正急的事都会打电话，而打电话的人根本不在乎你的番茄钟。外部打断则可以谈：把"随时找我"改成"我下午两点到五点有焦点时间，急事打电话"，大多数人会尊重一个明确的时间承诺，前提是这个承诺真的写在了日历上。

想量化这种碎片化，把一天的日程导出来跑一遍就知道：

```python
"""估算一天的会议碎片化程度：连续安排之间的间隙越短，碎片化越高。"""
from datetime import datetime

def gaps(events):
    spans = sorted(
        (datetime.fromisoformat(s), datetime.fromisoformat(e))
        for s, e in events
    )
    return [
        (later[0] - earlier[1]).total_seconds() / 60
        for earlier, later in zip(spans, spans[1:])
    ]

day = [
    ("2025-03-11T09:30", "2025-03-11T10:00"),
    ("2025-03-11T10:10", "2025-03-11T11:00"),
    ("2025-03-11T11:05", "2025-03-11T12:00"),
]
all_gaps = gaps(day)
short = [g for g in all_gaps if g < 20]
print(f"共 {len(all_gaps)} 个间隙，其中 {len(short)} 个不足 20 分钟")
```

间隙不足二十分钟的日子，人是一路小跑切完任务的，这种日历形状比任何工时统计都更能说明疲惫的来源。

## 条目二：深度工作块，把时间当会议室订

Paul Graham 讲过 maker's schedule：创造者的时间是整块的，一小时对一个做东西的人意义有限，就像一块只有一半算力的 CPU。实践上，深度工作块就是把两到四小时锁进日历，像锁会议室一样锁自己：状态设为忙碌、自动拒绝新邀请、戴耳机当物理信号。管理者的日历就是团队的日历，你自己天天碎片化，团队一定有样学样，这一点怎么强调都不过分。

### 可抄的模板

<details>
<summary>展开：一份可抄的深度工作块模板</summary>

- 上午 9:00 到 11:30，深度块
  - 不排会、不看消息、不开分支评审
  - 最难的题放这里，邮件和审批放下午
- 11:30 到 12:00，消息窗口
  - 集中回复，顺手清一次通知
- 下午 14:00 到 17:00，协作时段
  - 会议、评审、结对都放进这里
- 17:00 到 17:30，收尾
  - 记下明天的第一个动作，降低次日启动成本
</details>

有个反直觉的点：深度块不需要每天都有，一周三个完整块胜过七个残破的半天。日历上留白本身就是产能，而把留白填满的那个动作，往往发生在你正忙到没空思考的时候。

> 深度块的质量不看时长，看中途被打断的次数。一个不被打断的两小时，价值超过四个被切碎的半小时。

每次有人跟我说"实在排不出整块时间"，我的建议是先统计一周日历：你会发现被切碎的半小时远比想象中多，只是它们都伪装成了"顺手处理的小事"。

## 条目三：异步通信为什么是解药

同步沟通把成本压在"此刻必须有空"的每个人头上；异步沟通把成本转移到写作上，而写作恰好可以摊销：一段写清楚的文档，被读十次还是写一次的成本。GitLab 的 handbook-first 文化把这套推到极致：任何决策先写文档，评论在文档上长出来，会议只在文档吵不出结果时才开。判断标准很简单：这件事需要来回几轮才说得清，就写文档；需要几分钟内对齐情绪和底线，才开会。

把问题写清楚有三要素，缺一个就会被反问三轮：

- 背景：系统现在什么样，观察到的现象是什么
- 已试过什么：避免别人重复你的排查路径
- 要什么：一个决定、一次评审，还是只想让人知道

工程上还可以更进一步，把例行的异步同步自动化。比如每周一自动开一个站会 issue，模板就是焦点、阻塞、需要谁看到三项，评论即回复，会议日历上干干净净：

```yaml
# 每周一自动创建异步站会，评论即回复
name: async-standup
on:
  schedule:
    - cron: "0 1 * * 1"   # 北京时间周一上午九点
jobs:
  open:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/github-script@v7
        with:
          script: |
            await github.rest.issues.create({
              owner: context.repo.owner,
              repo: context.repo.repo,
              title: `异步站会 ${new Date().toISOString().slice(0, 10)}`,
              body: "## 本周焦点\n\n## 阻塞\n\n## 需要谁看到"
            })
```

## 条目四：给自己设计一个开工仪式

切换成本里最冤的一种，发生在每天第一次坐下的时候：昨天还记得的上下文，过了一夜需要重新加载。开工仪式就是把这个加载过程固定成几个动作，省得每天现想"我昨天干到哪了"。我的仪式只有三步：看昨天的收尾记录、跑一遍昨天的测试确认基线还是绿的、在便签上写下今天要动的第一个文件。全套十分钟，但它把"进入状态"从意志力问题变成了流程问题。

仪式的设计原则可以套用任何降低启动成本的场景：

- 第一步永远小到不可能失败
  - 比如"打开昨天那个文件"，而不是"开始重构模块"
- 每步都有明确的完成信号
  - 测试绿了、便签写好了，都是信号
- 全程不超过一刻钟
  - 超过就成了新的上下文负担
- 头天收尾时给第二天留钩子
  - 一句"下一步改 X 函数的第二个分支"就够用

反过来，没有仪式的日子，人会用刷手机来完成"加载"，刷着刷着半小时就没了。这不是自律问题，是大脑在找不到明确起点时，会自动挑选最省力的刺激。给它一个明确的起点，它就不到处找了。

参考：[每日开工仪式实践](https://example.com/daily-startup-ritual)

## 条目五：团队能动手做的几件小事

文化是慢慢变的，但有几件事下周就能做：日历上设一个全员无会日，让大家有整块时间的预期；即时通讯的置顶里放一份焦点时间公约，写明什么情况可以打断、什么情况等消息窗口；管理者把自己的深度块晒出来，比发十封倡议邮件管用。还有一条常被忽略：减少"以防万一"的订阅。日报、周报、全量告警邮件，每一条都在别人的深度块上收税，而收上来的多半没人看。

- 日历上有一个固定的无会日
- 团队公约写明了可接受的打断方式
- 告警按"需要人行动"过滤，其余进日报
- 每月回顾一次：上周每人有几个完整深度块

最后提醒一句度量姿势：这些事的收益是"没被浪费的时间"，天然难以观测，别指望画出漂亮的曲线。能看到的间接信号是缺陷重开率下降、评审轮次变少，以及大家开始主动拒绝无议程的会议。信号会滞后半年出现，但它们比任何自评问卷都诚实。

参考：[远程团队协作公约模板](https://example.com/remote-collaboration-norms)
