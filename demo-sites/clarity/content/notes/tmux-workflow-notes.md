远程开发绕不开终端，终端里绕不开 tmux：SSH 断线不丢现场、一个屏幕同时看编辑器和日志、长任务挂后台随便看。这篇笔记收两层内容：会话、窗口、窗格三层结构的最小心智模型，和我在日常开发里真正每天敲的命令。配置放在文末，可以直接抄。先交代适用边界：tmux 解决的是终端会话的管理，不解决编辑器选型，也不解决服务器配置。本地 macOS 或 Linux 桌面用户受益最大，纯 Windows 图形环境用户可能需要先过 WSL 那一关。想清楚它管什么，就不容易在它身上期待错东西。

## 三层结构：会话、窗口、窗格

tmux 的世界只有三层，理解这层关系，命令一个都不用背，因为所有操作都是"对哪一层的哪个对象做什么"：

- **会话（session）**：工作的容器。一个项目一个会话，断开 SSH 后会话还在服务器上活着。
- **窗口（window）**：会话里的全屏页，相当于浏览器标签页。一个窗口干一类活。
- **窗格（pane）**：窗口内的分屏，同一屏里并排放几个终端。

刚学时最容易混的是窗口和窗格的区别，记住一个类比就行：窗口是标签页，窗格是分屏。需要"同时看到"的用窗格，需要"随时切换"的用窗口。会话和服务器进程的关系也值得说透：tmux 服务端是独立进程，会话里的程序挂在它名下，SSH 断开只是断开了你的查看通道，进程树原封不动。这就是"断线不丢现场"的全部秘密，不是什么魔法，就是一层进程托管。tmux 的百科条目在 <https://zh.wikipedia.org/wiki/Tmux>，三层结构讲得比多数教程清楚。初学者常见的错误是一上来就抄配置，结果每个选项都不知道在管什么，出问题只能整段删掉。先建立三层结构的心智模型，再谈配置，顺序反了事倍功半。

| 层级 | 类比 | 前缀后按键 | 常用场景 |
|------|------|-----------|----------|
| 会话 | 项目工作区 | `d` 脱离、`s` 切换、`$` 重命名 | 一个项目一条会话 |
| 窗口 | 浏览器标签页 | `c` 新建、`n`/`p` 切换、`,` 重命名 | 编辑、测试、运维分开 |
| 窗格 | 分屏终端 | `%` 左右分、`"` 上下分、`x` 关闭 | 编辑配日志同屏 |

默认前缀是 <kbd>Ctrl</kbd>+<kbd>b</kbd>，所有快捷键都要先按它。这个组合按久了小指难受，我的建议是改成 <kbd>Ctrl</kbd>+<kbd>a</kbd>，和屏幕的前缀同源，手指也顺。改法在文末配置里。

## 我的日常布局

### 编码加服务加日志

三窗格是黄金布局：左边编辑器，右上跑服务，右下看日志。两件需要"瞄一眼"的事和主任务放在同一屏，眼睛不用在窗口间追，心流就不容易断。

```bash
# 建会话、切三格、各就位
tmux new-session -s dev -d
tmux split-window -h -t dev
tmux split-window -v -t dev
tmux send-keys -t dev:0.0 'vim .' C-m
tmux send-keys -t dev:0.1 'npm run dev' C-m
tmux send-keys -t dev:0.2 'tail -f logs/dev.log' C-m
tmux attach -t dev
```

`send-keys` 的作用是往指定窗格"按键"，等于替你把命令敲进去再回车。整套脚本化的价值在于可复现：项目 checkout 到新机器，一条命令重建全套现场，不用凭记忆摆窗口。命名规范上我给窗格也起名，切换时用名字不用编号，`send-keys` 的目标也不怕顺序变动。脚本放项目仓库里，新人第一天就能复制一套可用的开发环境，这种 onboarding 体验比任何文档都直接。

### 布局一键切换

tmux 自带五种预设布局，日常两种够用：

```bash
tmux select-layout -t dev even-horizontal   # 左右均分
tmux select-layout -t dev main-vertical      # 左侧大右侧竖排
```

写代码时用 main-vertical，编辑器独占左边，右边竖排服务和日志；对 Log 时用 even-horizontal，两栏一样宽看得全。切换是幂等的，随时按随时生效，比手动拖边框快得多。两种布局之外，`tmux capture-pane` 还能把某个窗格的当前内容抓下来存文件，日志取证、贴工单都好用。窗格里的输出不只属于屏幕，也能变成文件，这个能力很多人不知道。

## 窗口命名与会话组织

窗口和会话的命名是运维体验的分水岭。默认名字是 bash、vim 这种进程名，切三个窗口之后全靠位置记，超过五个必乱。我的规矩：会话名用项目名，窗口名用职责名，一建好就改，别拖延。

```bash
# 建会话时顺手把第一个窗口改名为 edit
tmux new -s api -d -n edit
tmux new-window -t api -n test
tmux rename-window -t api:0 logs
```

切换用名字不用编号，`tmux select-window -t api:test` 比 `:2` 抗改动。会话多了之后配个别名看全景，`tmux ls` 的输出按名字排序，扫一眼就知道哪个项目有现场。这套组织方式的额外好处是交接：同事接手时 `tmux ls` 加窗口名，现场结构一眼看懂，不用你画图讲解。

## 与 vim 和 git 的配合

tmux 和编辑器是天然搭档，三窗格里跑 Vim 的体验和 IDE 分屏几乎对齐。有一个细节值得调：Vim 里配色在 tmux 下偶尔失真，是终端类型声明的问题，tmux 里设 `set -g default-terminal "tmux-256color"`，Vim 里配 `set termguicolors`，两边对齐之后真彩色才正常。折腾一次，受益所有会话。

跑长时间命令时的组合技更实用：tmux 里跑 git 大操作，断了线重连回去接着看输出，比裸终端里提心吊胆强。`git gc`、大仓库 `git log`、批量 cherry-pick，我都习惯先开个 tmux 会话再开工，等于给危险操作上了保险。写提交信息时还能在窗格里 Vim 和命令行来回看 diff，一个屏幕全看见。

## 值得记住的命令

### 会话管理

```bash
tmux ls                    # 列出所有会话
tmux attach -t dev         # 接入指定会话
tmux new -s scratch        # 新建并进入
tmux kill-session -t dev   # 结束会话
```

接入已存在的会话是远程开发的日常：SSH 上去 `tmux ls` 看一眼，`attach` 上去就是昨晚的现场，跑着的服务、开着的日志、光标位置，全在。断线在 tmux 里叫脱离，`d` 键或者直接关终端都行，会话里的进程不受影响，这是它相对裸终端最核心的价值。有个排错经验顺带记下：attach 不上、提示 sessions should be nested，说明你已经在 tmux 里又 attach 了一次，用 `tmux switch-client` 切会话，别嵌套 attach，两层前缀能把手绕晕。

### 复制模式

复制模式里 `g` 跳到顶部、`G` 跳底部、`/` 在历史里搜索，翻几千行日志时和 Vim 键位完全一致，`mode-keys` 设了 vi 就是这个好处。复制到的内容默认进 tmux 内部粘贴板，跨窗格粘贴用前缀加 `]`，跨程序粘贴才需要系统剪贴板那行配置。

---

> tmux 的价值不在花哨，在"断线重连后现场还在"。为这一点，值得把前缀键从 Ctrl+b 改成 Ctrl+a，也值得花半小时把布局脚本化。工具的钱，本质是买"现场不丢"这四个字。

## 可复制的配置

<details>
<summary>点开：直接可用的 tmux.conf 片段</summary>

```text
# 前缀改成 Ctrl+a，松掉原前缀
set -g prefix C-a
unbind C-b
bind C-a send-prefix

# 鼠标支持，懒人福音
set -g mouse on

# 历史行数，日志翻查靠它
set -g history-limit 50000

# 分屏快捷键更顺手
bind | split-window -h
bind - split-window -v

# 复制模式走 vi 键位
setw -g mode-keys vi
```

</details>

配置生效两种方式：重开一个会话，或者当前会话里 `source-file ~/.tmux.conf`。改前缀之后第一次用会别扭两天，之后再也回不去，属于典型的"短期成本长期收益"。鼠标支持打开之后，滚轮翻历史、点击切窗格都直接能用，但快捷键别扔，鼠标是补充不是替代。还有两个隐藏开关值得知道：`set -g base-index 1` 让窗口从 1 开始编号，和前十个窗口的 <kbd>Ctrl</kbd>+<kbd>a</kbd> 加数字切换对得上；`set -g renumber-windows on` 关掉窗口后自动重排编号，不留空洞。两个开关各一行，强迫症福音。

## 一条建议收尾

如果只记一条，记这个：长任务一律在 tmux 里跑。训练模型、全量测试、数据同步，直接裸跑，SSH 一抖全部重来；丢进 tmux 会话，随便断线重连，任务自己长在服务器上。这个习惯改过来之后，晚上合上笔记本不再有心理负担，因为你知道现场还在。从裸终端到 tmux 的学习成本大约一小时，覆盖这篇笔记的全部内容足够。一小时换"随时断线、现场永驻"，是我这些年性价比最高的一笔工具投资。
