# .ai/prompts

审计与性能轮的提示词，以及配套的起点自检探针。放这里是为了让流程在仓内可复现：提示词、探针、判读规则都在版本控制里，换人或换会话不必重新口述。

## 文件

| 文件 | 用途 |
| --- | --- |
| `flint-audit-and-perf.md` | 唯一入口。一个文件覆盖三种轮次，用 §S 的开关切换：`F` 三轴（漏洞为主）、`PF` 性能优先（默认）、`P` 单轴性能。另有深度开关 `quick / standard / deep` |
| `fix-presence-probe.sh` | 起点自检：按锚点 grep 本项目历次审计的修复标记，输出 PRESENT / ABSENT |

## 用法

```bash
bash .ai/prompts/fix-presence-probe.sh          # 全 PRESENT 才继续
# 然后把 flint-audit-and-perf.md 全文交给执行方，并在任务开头写明开关：
#   模式=PF，深度=standard
```

执行方必须先解析开关并输出"生效清单"（哪些段落必做、预算怎么分），未输出就开工视为流程违规。

## 开关怎么选

| 场景 | 模式 | 深度 |
| --- | --- | --- |
| 刚换过大量代码，想同时查漏洞与提速 | `F` | `standard` |
| 只想提速，安全性作为门禁 | `PF` | `standard` 或 `deep` |
| 时间紧，只看端到端热点 | `P` | `quick` |

## 维护

- 探针新增条目时，同时把对应修复锚点写进提示词的"已知事实"或代码注释，避免探针与代码脱节。
- 修复若被回滚，探针会自然变红，这是预期行为，不要为了让探针变绿而放宽匹配串。
- 提示词的版本与日期写在文件头；口径变化（构建形态、测试通道、TFM）在同一提交里同步。
- 三种模式共用同一套门禁与证据纪律，只在"是否审计漏洞"和预算分配上不同；新增规则先想清楚它属于哪一档，别再拆出第二个文件。
