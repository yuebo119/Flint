## 3. 写入瓶颈定性（IO 微基准，10000 目录 × index.html）

| 模式 | 耗时 |
|---|---:|
| 现状（mkdir+async write 混合，dop=8） | 3165ms |
| 现状（dop=32） | 3227ms |
| 现状（dop=64） | 2746ms |
| 现状（dop=128） | 2767ms |
| 同步写（dop=64） | 2631ms |
| **仅目录创建（10000 个，dop=64）** | **1947ms** |
| 仅文件写入（目录已备，dop=64） | 1484ms |

**结论**：
1. **目录创建占写入开销大头**（NTFS 元数据操作），并行度 8→128 几乎无差——文件系统内部
   串行化，应用层并行无效
2. 现状混合模式（mkdir+write 同 worker 交错）已天然重叠两阶段，"先建全部目录再写文件"
   反而更慢（1947+1484=3431ms > 2746ms）
3. 同步写比 async 写快约 4%（避免 overlapped IRP 开销）
4. **生产写入 2383ms 已接近微基准物理天花板（2631ms）附近**——NTFS 上剩余优化空间
   约 5~10%；该成本为平台属性（Hugo 写同样 10006 个文件承担同样开销）

## 6. 并发加速比 1.08~1.12x 的相位分解（2026-09-25 · 1000 页 · 进程内套件）

> 数据：`FLINT_TRACE_PHASES` 套件日志中"并发构建性能"两腿（parallelism:1 vs
> Environment.ProcessorCount，同站点同进程交替构建）；本表取单/多线程各一轮实测。

| 相位 | 单线程 | 多线程 | 并行效果 |
|---|---:|---:|---|
| 1.配置加载+短码 | 311.9ms | 315.4ms | ❌ 无（串行） |
| 2.扫描内容 | 105.5ms | 107.3ms | ❌ 无（文件枚举 IO，未并行化） |
| 3.解析 | 9.8ms | 1.7ms | ✅ -83%（Channel 并行生效） |
| 8.渲染页面 | 194.4ms | 127.5ms | ✅ -34%（并行生效） |
| 11.写入输出 | 175.8ms | 179.6ms | ❌ +2%（NTFS 墙，与 §3 微基准 dop 8→128 零敏感互证） |
| 其余串行段 | ~22ms | ~22ms | ≈ |
| **总计** | **818.6ms** | **759.4ms** | **1.08x** |

**判定（回答"IO / 锁 / AOT 线程池"三选一）**：
1. **主瓶颈 = IO（NTFS 写入墙）**——写入相加线程零收益，与 §3 微基准互证，平台属性。
2. **次瓶颈 = 串行段占比 82%**（配置+短码 315 + 扫描 107 + 写入 180 + 其余 ≈626/759ms）——
   Amdahl 上限 ≈ 759/626 = **1.21x**，实测 1.08x，现有结构下剩余理论空间仅 ~12%；
   **要有意义的多核收益必须削减串行段本身**，不是调并行参数。
3. **排除锁与线程池**：渲染 -34%、解析 -83% 证明并行通路健康。本指标为进程内
   JIT 套件实测；AOT 端到端以写入 IO 墙为主（§1 AOT 写入占 74.5%），结论同为
   IO 墙 [推断]。
4. 可行动项：**配置+短码 315ms 占单腿总时 41%**，且首轮构建仅 0.8ms、后续构建
   恒为 ~315ms（394× 差异归因未明，疑杀软扫描 layouts/短码文件）——若坐实，
   这是比并行度更大的单一串行标的；动手前先复测归因。
