## 3. 写入瓶颈定性（IO 微基准，10000 目录 × index.html）

| 模式 | 耗时 |
|---|---:|
| 现状（mkdir+async write 混合，dop=8） | 3165ms |
| 现状（dop=32） | 3227ms |
| 现状（dop=64） | 2746ms |
| 现状（dop=128） | 2767ms |
| 同步写（dop=64） | 2631ms |
| **仅目录创建（10000 个，dop=64）** | **1947ms** |
| 仅文件写入（目录已备，dop=64） | 1484ms |

**结论**：
1. **目录创建占写入开销大头**（NTFS 元数据操作），并行度 8→128 几乎无差——文件系统内部
   串行化，应用层并行无效
2. 现状混合模式（mkdir+write 同 worker 交错）已天然重叠两阶段，"先建全部目录再写文件"
   反而更慢（1947+1484=3431ms > 2746ms）
3. 同步写比 async 写快约 4%（避免 overlapped IRP 开销）
4. **生产写入 2383ms 已接近微基准物理天花板（2631ms）附近**——NTFS 上剩余优化空间
   约 5~10%；该成本为平台属性（Hugo 写同样 10006 个文件承担同样开销）
